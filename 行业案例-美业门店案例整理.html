5. 跨案例共性规则（验证时优先盯住）

  1. 价目不只一种形态：固定价、区间价、双轨渠道价、同名多规格、技师档位价并存。
  2. 卡项是「权益包」：储值 + 次卡/任选 + 券 + 生日礼 + 转介，常叠加短/长有效期与不可退。
  3. 充值当日权益常绑余额约束（如消费不超过 40% / 留存不低于 60%）。
  4. 提成是多方案、多角色、多基数：比例 / 固定额 / 人头人次 / 卡销 / 耗卡子类 / 阶梯营业额 / 计件手工可同时存在。
  5. 开单协作：办卡 2～3 人分摊；烫染手工与发型师业绩可并存。
  6. 员工侧有「等级 + 底薪 + 考核门槛 + 方案绑定」完整链，不仅是一个提成百分比。

S4 计件手工分档（支数单价） 同上 是否可配置 缺口（仅按项固定额，无按支数分档计件）
S5 按角色比例（35%/15%/10%） 美发提成案例 方案或开单角色 部分覆盖（工位业绩占比可配；无 35/15/10 自动分摊演示）
S6 美容师等级：底薪+考核+人头/人次/卡销/耗卡子类 分级薪酬表 原型能否拆成多规则 部分覆盖（有底薪/奖惩/卡销卡耗等块；无等级考核与人头人次规则引擎）
S7 耗卡子类不同比例（消卡 vs 艾灸） 分级表 业绩计算口径 缺口（仅通用卡耗提成，无消卡/艾灸子类）
S8 学徒按 C 类套用 分级表 方案复用 部分覆盖（学徒可绑独立方案如 sch3；无「套用 C 类」继承关系）

6.5 可靠性与演示边界（建议记录）

# 问题 记录
R1 哪些规则仅有 UI、无真实计算？ 提成方案（含阶梯/按项固定额）、业绩基础口径（赠送/抵用券/免单）、卡耗入账多为配置 UI；收银落流水时 commission 常为 0，工资/提成明细大量靠种子或手填。
R2 多人分摊小数如何进位？ 有通用 round2；开单多员工无自动均分/工位比例拆分进位策略；流水编辑可手填后再汇总。
R3 活动价 / 赠金 / 划卡是否进入「实收业绩」？ 口径设置存在但不统一：新结算偏实收；划卡种子可走标价业绩；赠金/卡耗是否计业绩仅停留在设置文案。
R4 与资料冲突的默认演示数据是否误导验收？ 会。流水种子提成多为 0；工资月与提成明细为预置演示；购物车多员工未完整写入流水；勿把演示数字当规则引擎验收依据。

7. 建议验收顺序

  1. 美发价目 + 产品规格（结构清晰、易对照系统表）
  2. 办卡 / 次卡任选 / 有效期（宠粉卡、新客卡）
  3. 开单多员工 + 美发角色提成文案
  4. 美甲充值约束（专门找缺口）
  5. 美容师多维提成表（作为「高阶规则」压力测试）
