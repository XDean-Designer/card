先读这几条（贯穿全文）

  1. 新系统用 权益组合（面值 / 项目 / 产品 / 折扣）建卡，不再选「五种卡类型」；整套取代旧会员卡系统。
  2. 创建固定 三步：基本信息 → 权益组合 → 用卡策略；Step2 至少开启并配置一类权益。
  3. 当前有效持卡数 > 0 时模板 不可编辑（可复制建卡、可下架、可经结账办卡/退卡/延期）。
  4. 已下架不可新办；已持卡仍可退卡/延期；可重新上架或复制建卡。
  5. 会员卡分组：列表可按分组筛选；支持分组管理（新建/重命名/删除/拖排序）、编辑成员、列表「快速分组」；一张卡可同时属于多个分组。
  6. 办卡：选择会员 Sheet 单选一位未持卡会员 → 「去结账」 → 确认办卡（会员/卡锁定；应付默认可改；办卡日期可改；服务员工必选 ≥1；是否选工位取决于业绩设置·办卡业绩：按工位分配则每人必选工位，平均分配则不要求）→ 开单记账完成支付 → 支付成功回调后才写持卡与办卡业绩 → 办卡成功（来自结账时底栏可为「返回开单」）。演示种子默认办卡业绩为 按工位分配，便于完整演示选工位。
  7. 退卡为 整卡退；建议退款可按策略计算，实际退款金额可改后确认；本期 仅结束持卡 + 记实退，不走支付原路退款通道。
  8. 用卡策略两轨独立；公式随卡型（组合 / 纯折扣 / 不限次）变化；均值分母为面值 + 有限次项目权重 + 产品数量权重。
  9. 金额字段统一 元、两位小数；接口路径/字段名以联调为准；标 【待联调确认】 处不臆造现网 URL。开单支付交接契约见 §7.7（已定稿）。

交互行为与文案以 demo.html 当前表现 为准；本文把规则与验收写全，便于无历史上下文的机器与人直接开工。

模块 1　背景 / 目标 / 范围 / 能力映射

读者：前端 ✓ · 后端 ✓ · 测试 ✓

1.1 背景

原先的会员卡系统将卡划分为 5 种固定类型，每种类型套用 预设模板字段。商户创建会员卡时：

  • 只能在类型预设内填字段，自由度不足；
  • 每次都要面对 繁复的设置页 逐项填充，创建成本高。

本期交付的「会员卡管理」将 整套取代 上述旧系统（非长期并行两套产品线），对字段按能力重新解构。

1.2 目标

目标 说明
取代旧系统 新建模与流程成为唯一建卡体系
能力覆盖 可配置出与旧五类 功能等价 的卡，也可配置旧体系 无法做出 的组合卡
创建更简 三步完成：基本信息 → 权益组合 → 用卡策略
运营闭环 列表 / 分组 / 详情 / 上下架 / 复制 / 办卡 / 延期 / 整卡退卡
策略可配置 退卡消耗与员工业绩规则在建卡时选定并随模板保存

1.3 本期做（In）

  • 会员卡模板：创建、编辑（无持卡时）、复制建卡、在售/已下架列表与详情
  • 会员卡分组：自定义分组（名称 ≤20 字、不可重名）；列表筛选轨（全部 + 分组 + 齿轮进管理）；分组管理（拖排序 / 新建 / 重命名 / 删除）；编辑成员（多选卡入组）；列表「快速分组」Sheet（多选加入，可同时属多组）；删除分组 不删卡

  • 权益组合：面值（金额与赠送；仅可用于支付不含面值的办卡/购卡、收费延期及项目消费；不可用于含面值办卡、不可购买价目产品）、项目（每项/共计、购买/赠送/不限次；每项拆成一项目一票）、产品（行内数量，一种产品一票，不可不限量）、折扣（比例/固定金额）；均可配置多张权益 ticket

  • 卡面主题色（5 色：蜜桃/薄荷/雾霾/香芋/奶茶，默认蜜桃）、卡有效期限（日/月/年/永久；含项目/产品/折扣时受期限约束；含不限次项目时不可为永久）

  • 用卡策略：消耗及退卡计算规则、业绩计算规则（含总权益面值明细）
  • 办卡：单选既存会员 → 「去结账」→ 确认办卡（应付可改、办卡日期、服务员工）→ 开单记账支付 → 支付成功回调入账 → 办卡成功
  • 已持卡：延期（免费立即写；收费须支付成功后再写；纯面值或模板永久点延期 toast「该卡永久有效，无需延期」）、整卡退卡（估值 + 实退可改；仅记账）
  • 上下架及文案提示
  • 旧入口全量替换（见 §1.6）：工作台「卡管理」/ 会员卡管理 / 顾客详情 / 开单办卡 / 旧卡搜索详情 / 认领·AI 录卡等一律切新模板体系

1.4 本期不做（Out）

  • 开单记账支付页 UI 全链路规格 — 不在本文展开；但办卡/收费延期 必须依赖开单模块收款，交接字段与回调见 §7.7（未就绪时 toast「开单记账模块未就绪」）
  • 价目表作为独立产品交付 — 不在本文展开；规格见同目录 PRD-项目创建与管理.md。建卡「选项目/产品」与「管理价目表」依赖价目数据（项目 Tab / 产品 Tab）。会员卡域金额以 元 为准（见 §7.8）；与价目「存分」建议冲突时以本定稿为准
  • 会员管理（会员 CRUD；办卡仅从既存会员列表 单选）
  • 部分退卡、劳动业绩独立运算台、预约联调
  • 退卡资金原路退 / 退款渠道选择 / 退款成功回调后再改持卡 — 本期不做（见 §6.11、§7.4）
  • 原型工具栏「无数据/有数据」造数按钮 — 仅演示，不进正式产品

1.5 旧能力 ↔ 新组合权益（能力映射，不写废弃产品名）

旧体系常见能力（语义） 新体系如何配置
储值/充值类（买赠面值） 开启 面值：填面值金额；赠送 = 面值 − 购买金额（自动）；持卡面值 仅可支付不含面值的办卡/购卡、延期与项目消费；不可支付含面值新办卡，不可购价目产品
次卡/项目次数类 开启 项目：选适用项目；每项或共计；购买/赠送次数或不定次；保存后每项 = 一项目一 ticket
产品次数/礼品类 开启 产品：行内设数量（qty≥1 为已选）；一种产品一张 ticket；禁止不限量
折扣/会员价类 开启 折扣：选适用项目；标尺折扣或固定金额
期限卡 Step1 有效期限；含不限次项目时不可为「永久」；含项目/产品/折扣时须设妥期限
组合（储值+项目+折扣等） Step2 同时开启多类权益 并分别配置
旧类型无法覆盖的组合 任意权益开关组合 + 独立用卡策略

映射不足时 以新字段与原型行为为准，不编造旧系统字段表。

1.6 旧入口全量替换（本期 In）

产品线定位：整套取代旧五类型会员卡系统，非长期双轨。下列入口本期必须切新模板体系与新 API，禁止再走旧类型建卡/办卡接口：

入口 要求
工作台 · 卡管理 进入新版会员卡管理（页标题「会员卡管理」）
会员卡管理主列表 / 详情 新模板权益模型
顾客详情 · 办卡 / 持卡 新办卡 / 持卡流程
开单 · 办卡 / 添加卡 确认办卡 → 开单支付契约（§7.7）；不复用旧卡类型选择
旧卡搜索 / 详情 切新详情；历史卡只读兼容
认领卡 / AI 录卡 写入新模板权益模型；或仅迁移历史数据、不可新建旧类型

历史数据：旧类型已发卡可只读展示，退卡/延期按 §1.5 映射解释；不可再创建旧类型卡。

2.2 核心场景

场景 用户期望
首次建卡 三步填完保存 → 上架 → 可立即办卡
配置组合权益 面值/项目/产品/折扣按需勾选配置，预览卡面
分组运营 新建分组 → 编辑成员或快速分组 → 列表按组筛选；空组可「添加卡到本组」
有持卡后改规则 不能直接编辑模板；复制建卡后改新卡
停售 下架后新客不能办；已持卡不受影响
再开售 重新上架后可再办
为会员办卡 单选未持该卡的会员 → 「去结账」→ 确认办卡（改应付/办卡日期、选服务员工；演示默认还须选工位）→ 开单记账支付 → 办卡成功
延期 对有期限权益持卡设置延期时长；含折扣且参考费用 > 0 时走开单同款支付页，支付成功后再写延期；费用为 0 或选永久则立即生效；纯面值/模板永久仅 toast 无需延期
退卡 看到建议退款与明细，改实际退款后确认整卡退；结束持卡并记实退（不走支付退款通道）

2.3 成功标准（可判定）

  1. 空店可创建至少一张在售卡并出现在「在售」列表。
  2. Step2 至少有一类已配置有效内容的权益 才能进入 Step3 / 保存成功；开关已开但无内容时 自动关闭该开关（不拦截下一步，见 5.2 / 6.3）。
  3. 当前有效持卡 > 0 时详情「编辑」不可用，并提示复制建卡。
  4. 已下架卡列表无「办卡/退卡」入口；详情可「已持卡管理」（退卡/延期）。
  5. 支付成功办卡后，持卡人数/办卡次数等运营数据按规则增加；入账金额以确认办卡页应付为准。
  6. 退卡确认后该会员不再作为有效持卡；进入退卡成功页，实退金额以确认值为准展示。
  7. 有卡时列表展示分组筛选；空组筛选显示「本组暂无会员卡」并可进入编辑成员。

8.4 消耗及退卡计算规则

统一：

[ \text{建议退款} = \max(0,\ P - \text{消耗价值}) ]

实退金额商户可改；确认后 仅结束持卡 + 记实退，不走支付退款通道。

8.4.1 均值退卡（refundRule = alloc_pool）

A. 纯折扣

[ \text{消耗} = P \times \frac{\text{已过天数}}{\text{总有效期}} ]

  • 有期限：总有效期 = 模板有效期对应天数（或持卡起止推算）。
  • 永久：总有效期按 1095 天（3 年）；已过满 3 年按满额消耗。
  • 「累计已享折扣优惠」仅作信息行，不计入消耗。

B. 组合卡（(W > 0)）

  1. 对每项计入 (W) 的权益：分摊 (A_i = P \times (w_i / W))。
  2. 面值行：按购买面值/赠送面值已用·剩余，分别乘系数（购买系数 (= A_{\text{面值}} / \text{购买初始})；赠送系数 (= A_{\text{面值}} / \text{面值合计})）累加得消耗与剩余。
  3. 有限次项目行：单次摊销 (= A_i / \text{总次数})；消耗 (= \text{已用次数} \times \text{单次摊销})（购/赠次数分别记账，合计计次）。共计池：合并组内已用/剩余后同上。
  4. 产品行：单件摊销 (= A_i / \text{数量})；消耗 (= \text{已用数量} \times \text{单件摊销})。
  5. 固定期限不限次且 (W = 0)（实付未被面值/有限次/产品分完）：整笔 (P) 按已过/总天数摊销（同时间摊销公式）。若 (W > 0)，不限次 不再另占 实付份额。
  6. 折扣行（非纯折扣）：消耗 (= \text{累计已省优惠})；不占购卡实付分摊份额；剩余价值记 0。
  7. 消耗价值 = 各行消耗之和。

8.4.2 减值退卡（refundRule = retail）

不按 (P/W) 比例切分项目消耗（面值行仍可借用分摊系数，与实现一致）：

行 消耗
面值 同均值面值行算法（系数相对 (P) 与面值权重）
有限次 · 每项 价目原价 × 已用次数
有限次 · 共计 组内原价均值 × 已用次数
折扣 累计已省优惠（计入消耗；明细注明不占实付份额）
产品 减值路径以原型为准；组合产品消耗主路径见均值

建议退款仍 (= \max(0, P - \text{消耗}))。

8.4.3 无分项估值

无可分项权益时：提示协商退款文案（见模块 9）；建议值可回落到按办卡实付协商。

  • 未选手动改价前：随时长变化自动重算。
